# sdd:brief-dev — 마커를 걷어 낸 개발자용 기획 문서

요구사항 문서를 받아 마커만 지운 사본을 쓴다. 개발자가 결정 표기 없이 문서를 처음부터 끝까지 읽게 하는 것이 목적이다. 코드는 바꾸지 않는다.

먼저 `${CLAUDE_PLUGIN_ROOT}/references/brief-format.md` 를 읽는다. 입력과 출력, 「변환 원칙」, 「마커 제거」, 「답 반영」은 그 문서를 따른다. 「개발 언어 순화」는 하지 않는다.

- `sdd:draft`: 이 스킬의 입력(requirements.md)을 쓴다
- `sdd:brief-nondev`: 같은 입력으로 비개발자용 `brief-nondev.md` 를 쓴다

## 입력 찾기

- 설명에 경로가 있으면 그 `requirements.md`. 폴더면 그 안의 `requirements.md`
- 없으면 `spec-format.md` 「저장 위치」의 「폴더 고르기」로 폴더를 고른다. 폴더가 하나도 없거나 고른 폴더에 `requirements.md` 가 없으면 쓰지 않고 "`/sdd:draft` 를 먼저 실행하세요" 한 줄을 남긴다
- 입력에 `(작성 중)` 이 남아 있으면 쓰지 않고, 그 절 이름을 알려 준다
- 설명에 "artifact", "아티팩트" 가 있으면 「공유 문서 경로」, 없으면 마크다운으로 쓴다

## 쓰는 순서

- 입력을 끝까지 읽는다. 앞부분만 보고 쓰지 않는다
- 채팅에 "{입력 폴더}/brief-dev.md 에 씁니다" 한 줄을 남긴다
- 「마커 제거」를 적용해 Write 로 한 번에 쓴다
- 검증한다. 하나라도 걸리면 고치고 다시 검증한다
    - 마커: `grep -nE '@(결정|해석|초안|미정|사실|가정|확정)' brief-dev.md` 결과가 없다
    - 표기 열: `grep -n '표기 |' brief-dev.md` 결과가 없다
    - 구조: `grep '^#' requirements.md` 와 `grep '^#' brief-dev.md` 가 같다
    - 번호: `grep -c '^[0-9]\+\. '` 가 입력과 같다
- spec-format 「윤문」을 거친다

## 공유 문서 경로

입력이 공유 문서 링크이거나 설명에 아티팩트 요청이 있을 때만 쓴다.

- 입력 문서를 읽는 도구와 새 문서를 만드는 도구는 `sdd:draft` 「공유 문서 경로」를 따른다
- 내용은 마크다운 경로와 같다. 공유 문서는 표를 그려 주므로 표를 그대로 둔다
- 다 만들면 문서 링크를 끝맺음 둘째 줄에 둔다

## 끝맺음

- 첫 줄: 다음 행동 하나
    - 열린 결정이 있으면: 다음에 답할 결정 하나와 추천안. 답은 `requirements.md` 에 반영된다고 붙인다
    - 없으면: 문서를 여는 행동 한 줄
- 둘째 줄: 문서 경로(클릭 가능한 `path`) 또는 링크
- 무엇을 지웠는지 불릿 5개 이하 (예: 마커 N개, 표기 열 N개). 문서 내용을 채팅에 다시 늘어놓지 않는다

## 하지 않는 것

- 코드를 바꾸지 않는다
- 조사하지 않는다. 결정·절·예시·그림을 더하지 않는다
- EARS 문장, 코드 경로, 「기존 시스템과 맞닿는 곳」을 바꾸거나 지우지 않는다
- 마스터 답을 brief-dev.md 에 반영하지 않는다. `requirements.md` 에 반영하고 다시 만든다
