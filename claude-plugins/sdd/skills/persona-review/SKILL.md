# sdd:persona-review — 참여자별 시나리오 검토

요구사항 문서 하나를 받아, 참여자마다 그 사람 입장에서 기능을 처음부터 끝까지 따라가며 빠진 과정을 찾고 같은 문서를 보강한다. 코드는 바꾸지 않는다.

먼저 `${CLAUDE_PLUGIN_ROOT}/references/spec-format.md`, `${CLAUDE_PLUGIN_ROOT}/references/draft.md`, `${CLAUDE_PLUGIN_ROOT}/references/persona-review.md` 를 읽는다. 결정·마커·답 반영은 첫 문서를, 요구사항 문서의 모양은 둘째 문서를, 검토 질문·에이전트 프롬프트·반영 규칙·기록 모양은 셋째 문서를 따른다. 이 스킬은 "어떤 순서로 검토하는가" 만 정한다.

- 문서를 쓴 사람이 다시 읽으면 쓴 흐름을 그대로 따라가서, 쓸 때 놓친 곳을 또 놓친다. 그래서 참여자마다 다른 에이전트가 새로 읽는다
- `sdd:draft` 가 참여자가 모두 확정(@결정)된 문서를 다 쓴 뒤 이 스킬을 부른다. 마스터가 이미 있는 문서를 보강하려고 직접 불러도 된다

## 입력 찾기

- spec-format 「저장 위치」의 「폴더 고르기」로 폴더를 정한다. 파일 경로를 받으면 그 파일이 있는 폴더다
- 폴더에 `requirements.md` 가 없으면 검토하지 않고 "`/sdd:draft {설명}` 을 먼저 실행하세요" 한 줄을 남긴다
- 문서를 끝까지 읽는다. 앞부분만 보고 검토하지 않는다

## 참여자 정하기

- 「{기능}이란」의 「참여자」 표에서 참여자와 하는 일을 읽는다
- 참여자에 @초안 이 붙어 있고 마스터가 직접 불렀으면, 검토 전에 `AskUserQuestion` 한 번으로 참여자 목록을 확인받는다. 확정되지 않은 목록으로 검토하면 검토 일부가 헛일이 되기 때문이다
    - `sdd:draft` 가 불렀으면 묻지 않는다. draft 는 참여자가 모두 @결정 일 때만 부른다
- 「참여자별 검토 기록」이 이미 있으면 기록에 없는 참여자만 검토한다 (persona-review.md 「다시 실행」)
- 참여자가 8명을 넘으면 하는 일이 비슷한 참여자를 묶어 8묶음 이하로 만든다. 묶은 이름은 기록에 `{참여자 A}·{참여자 B}` 로 적는다

## 검토

- 참여자 한 명(또는 한 묶음)에 `Agent` 하나를 띄운다. 모든 Agent 호출을 한 응답에 같이 보내 동시에 돌린다
    - `subagent_type: "general-purpose"`, `description: "{참여자} 관점 검토"`
    - 프롬프트는 persona-review.md 「에이전트 프롬프트」 원문에 자리값을 채운 것이다
- 모두 돌아오면 persona-review.md 「합치기」대로 같은 과정을 하나로 합친다
- 에이전트 하나가 실패하거나 빈손으로 돌아오면 나머지 결과로 진행한다. 그 참여자는 기록에 "검토 실패" 로 남기고 끝맺음에 한 줄을 적는다

## 반영

- 합친 빈 곳마다 persona-review.md 「빈 곳 보내기」대로 갈 곳을 정하고 Edit 로 같은 문서를 고친다. 새 문서를 만들지 않는다
- 새 결정은 「필요한 결정」의 다음 ID 로 올린다. 그룹마다 5개를 넘으면 `A`~`H` 안에서 그룹 문자를 하나 더 쓰고, 모자라면 기능을 나누자고 권한다 (spec-format 「열린 결정」)
- 「필요한 결정」이 "없음" 이었으면 그 줄을 지우고 새 결정을 쓴다
- 문서 맨 아래에 「참여자별 검토 기록」을 쓰거나 이어 쓴다 (persona-review.md 「검토 기록」)
- 고친 내용이 문서 다른 곳에 이미 있는지 검색해, 있으면 새로 쓰지 않고 그 자리를 가리킨다 (spec-format 「한 번만 쓴다」)

## 윤문

- 마스터가 직접 불렀으면 고친 뒤 spec-format 「윤문」을 거친다
- `sdd:draft` 가 불렀으면 거치지 않는다. draft 가 이 스킬이 끝난 뒤 한 번 거친다

## 끝맺음

- 첫 줄
    - 새 열린 결정이 있으면: 먼저 답할 결정 하나와 추천안
    - 없으면: "참여자 {n}명을 검토했고, 빠진 과정 {m}개를 반영했습니다"
- 둘째 줄: 문서 경로(클릭 가능한 `path`)
- 참여자마다 찾은 과정 수 한 줄씩. 문서 내용을 채팅에 다시 늘어놓지 않는다
- `sdd:draft` 가 불렀으면 끝맺음 대신 draft 에 "새 결정 {ID 목록}, 더한 인수 조건 {자리 목록}" 만 돌려준다. draft 가 자기 끝맺음에 합친다

## 하지 않는 것

- 코드를 바꾸지 않는다
- 마스터가 정한 규칙(@결정·@확정)을 고치지 않는다. 빈 곳이 이미 정한 규칙과 부딪히면 결정으로 올린다
- 에이전트가 돌려준 문장을 그대로 붙여 넣지 않는다. 문서 모양(EARS, 마커, 결정 모양)으로 바꿔 쓴다
- 「참여자별 검토 기록」에 규칙 내용을 쓰지 않는다. 반영한 곳만 가리킨다
