# 참여자별 시나리오 검토 (persona-review)

`sdd:persona-review` 가 요구사항 문서(requirements.md)를 보강할 때 쓰는 질문, 에이전트 프롬프트, 반영 규칙, 기록 모양이다. `references/spec-format.md` 를 모두 따르고, 고치는 문서의 모양은 `references/draft.md` 를 따른다.

## 검토 질문

에이전트마다 같은 질문을 준다. 표의 열이 아니라 검토할 때 떠올릴 힌트다. 질문에 맞지 않는 빈 곳도 찾으면 돌려준다.

| 질문 | 예 (제휴카페 임직원 할인) |
| --- | --- |
| 나는 내 숫자와 상태를 어디서 보는가 | 사장님이 보전받을 금액, 임직원의 이번 달 사용액 |
| 내가 시작할 때, 중간에 바뀔 때, 그만둘 때 어떻게 되는가 | 퇴사자 재인증, 한도를 달 중간에 줄일 때 |
| 다른 사람이 취소·거절하거나 동시에 움직이면 나는 어떻게 되는가 | 카페 쪽 취소, 결제 직전 다시 계산 |
| 돈이 안 오거나 늦게 오면 내가 손해를 보는가 | 회사 미납 |
| 내 정보가 누구에게 가는가 | 임직원별 내역을 회사에 주는 것 |

## 에이전트 프롬프트

`{…}` 자리만 채워 그대로 보낸다.

```text
너는 「{기능}」 기획의 참여자 "{참여자}" 다. 너가 하는 일: {하는 일}.
이 기능의 다른 참여자: {다른 참여자 목록}.

요구사항 문서 {문서 절대 경로} 를 끝까지 읽어라. 파일을 고치지 않는다.

"{참여자}" 입장에서 이 기능을 처음 시작할 때부터 그만둘 때까지 따라가며, 내가 참여해야 하는데 문서에 없는 과정을 찾아라. 다른 참여자가 움직여서 나에게 생기는 일도 포함한다. 아래 질문을 힌트로 쓰되, 질문에 맞지 않는 빈 곳도 적는다.

{검토 질문 표}

이미 문서에 규칙이 있는 과정은 적지 않는다. 짐작으로 문서 내용을 지어내지 않는다.

빠진 과정마다 아래 네 줄로 돌려준다. 없으면 "없음" 한 줄만 돌려준다.
- 과정: {한 줄 이름, 예: 보전받을 금액을 본다}
- 왜 필요한가: {이 과정이 없으면 나에게 생기는 일 한 줄, 숫자 예시가 있으면 숫자로}
- 가장 가까운 곳: {요구사항 n 인수 조건 m | 결정 ID | 절 이름 | 없음}
- 갈림: {채우는 방법이 하나면 "한 줄 규칙: …", 옵션이 갈리면 "옵션: a) … / b) …", 계약·가격·외부 합의면 "외부: {누가 정할 일}", 시스템 밖 일이면 "시스템 밖: …"}
```

## 합치기

- 과정 이름이 달라도 같은 상황·같은 규칙이면 하나로 합친다 (예: 회사 담당자의 "정산액을 못 낸다" 와 사장님의 "보전금이 안 들어온다")
- 합친 과정에는 찾은 참여자를 모두 기록한다
- "가장 가까운 곳" 이 문서에 이미 같은 규칙을 가진 자리면 빈 곳이 아니다. 버리고 기록에만 그 자리를 적는다
- 갈림이 에이전트마다 다르면 더 넓은 쪽을 쓴다 (한 줄 규칙 < 옵션 < 외부)

## 빈 곳 보내기

합친 빈 곳마다 하나로 보낸다.

| 갈림 | 보내는 곳 | 마커 |
| --- | --- | --- |
| 한 줄 규칙 | "가장 가까운 곳" 요구사항의 인수 조건 끝에 다음 번호로 더한다. 맞는 요구사항이 없으면 새 요구사항을 「요구사항 템플릿」대로 더한다 | @초안 |
| 옵션 | 「필요한 결정」에 다음 ID 로. spec-format 「열린 결정」 모양 그대로(구체 예시, 옵션, 추천안, 걸린 곳) | 추천안 @초안 |
| 외부 (계약·가격·외부 합의) | 「필요한 결정」에 다음 ID 로, 추천 없이 | @미정 — {누가 정할 일} |
| 시스템 밖 (매장 안내물, 계약서 조항) | 「기존 시스템과 맞닿는 곳」의 「별개 작업」 | 없음 |

- 새 결정이 걸린 인수 조건에는 결정 ID 를 괄호로 붙인다 (예: `@초안 (B3)`)
- 「요구사항」 절 첫 문장의 요구사항 개수와 출처를 새 요구사항에 맞게 고친다

## 검토 기록

문서 맨 아래 `## 참여자별 검토 기록` 절이다. LLM 이 다시 검토할 때 쓰는 기록이라 사람이 읽을 문장을 두지 않는다. `sdd:brief-dev`·`sdd:brief-nondev` 는 이 절을 옮기지 않는다.

- 첫 줄: "LLM 이 검토를 다시 돌릴 때 쓰는 기록입니다."
- 참여자마다 불릿 하나, 그 아래 확인한 과정마다 하위 불릿 하나
- 하위 불릿: `{과정} → {반영한 곳}`. 반영한 곳은 요구사항 번호·인수 조건 번호, 결정 ID, `별개 작업`, `범위 밖`, 이미 있던 자리 중 하나다
- 다른 참여자와 함께 찾은 과정은 끝에 `({참여자}와 함께 찾음)`
- 빈 곳이 없던 참여자는 하위 불릿 `빠진 과정 없음`, 실패한 참여자는 `검토 실패`
- 규칙 내용, 숫자, 결정 답은 쓰지 않는다 (spec-format 「한 번만 쓴다」)
- 마커를 붙이지 않는다

```markdown
## 참여자별 검토 기록

LLM 이 검토를 다시 돌릴 때 쓰는 기록입니다.

- 제휴카페 사장님
    - 보전받을 금액을 본다 → B1
    - 정가를 제휴가 아래로 내린다 → 요구사항 4 인수 조건 3
    - 회사가 정산액을 안 낸다 → C2 (제휴회사와 함께 찾음)
    - 매장에 할인 안내를 붙인다 → 별개 작업
- 제휴회사
    - 회사가 정산액을 안 낸다 → C2 (제휴카페 사장님과 함께 찾음)
```

## 다시 실행

- 「참여자별 검토 기록」이 있으면 기록에 있는 참여자는 검토하지 않는다. 「참여자」 표에 새로 생긴 참여자만 에이전트를 띄운다
- 새 참여자가 없으면 검토하지 않고 "새 참여자가 없습니다. 다시 검토하려면 기록에서 그 참여자를 지우세요" 한 줄을 남긴다
- 새 참여자의 결과는 기록 끝에 이어 쓴다. 이미 있는 참여자가 함께 찾은 과정이면 그 참여자 아래에도 한 줄을 더한다
