# Socratic Record (학습 흐름 기록)

대화를 **사용자 본인의 복습용 기록**으로 바꾼다. 독자는 오직 사용자 자신이며, 목적은 "내가 어떤 상황에서 어떤 사고를 해서 어떤 흐름으로 여기까지 왔는가"를 나중에 다시 훑는 것이다.

그래서 **요약해서는 안 된다.** 결론만 남긴 문서는 정답표이지 사고 기록이 아니다. 이 스킬이 만드는 것은 정답표의 반대편이다.

## 세 가지 축

1. **원문 보존** — 사용자의 답변을 한 글자도 고치지 않는다
2. **사고 복원** — 그 답변이 나온 경로를 `[사고]`로 재구성한다
3. **막힘 보존** — 틀린 답, 이해 못 한 질문, 되돌아간 구간을 지우지 않는다

## 사전 확인

기록을 만들기 전에 두 가지를 확인한다. 대화에서 이미 정해졌으면 묻지 않는다.

- **범위** — 이번 앵커만인가, 대화 전체인가
- **`[막힘]` 처리** — 남길 것인가 뺄 것인가 (기본값: 남긴다)

사용자가 "복습용", "내가 보려고", "다시 훑어보려고"라고 밝혔다면 `[막힘]`은 묻지 않고 남긴다. 그것이 이 문서의 핵심 정보다.

---

## 라벨 체계

socratic-tutor가 대화 중에 쓴 라벨을 그대로 계승하고, 기록에만 필요한 것을 더한다.

| 라벨 | 의미 | 출처 |
|---|---|---|
| `[목표]` | 그 구간의 앵커 | 대화 |
| `[사실]` | 진행자가 제공한 재료 | 대화 |
| `[상황]` / `[가정]` | 판단용으로 만든 장면 | 대화 |
| `[질문]` | 진행자가 던진 물음 | 대화 |
| `[응답]` | **사용자 원문** | 대화 |
| `[사고]` | 그 답이 나온 경로 | **기록에서 새로 씀** |
| `[정정]` | 어긋난 지점을 다시 판 구간 | 기록 |
| `[막힘]` | 질문이 이해되지 않아 재료를 다시 깐 구간 | 기록 |
| `[갈래]` | 정답이 아니라 설계 선택이 갈린 지점 | 대화/기록 |
| `[보류]` | 목표 밖이라 적어만 둔 것 | 대화 |
| `[지금까지]` | 확정된 것만 다시 늘어놓은 정리 | 대화 |
| `[도달]` | 앵커가 닫힌 지점 | 대화 |
| `[미해결]` | 끝내 안 닫힌 것 | 기록 |
| `[진행자 오류]` | 진행자 쪽 실수 | 기록 |

문서 맨 앞에 **라벨 범례 표를 반드시 싣는다.** 사용자가 몇 달 뒤에 열어도 라벨의 뜻을 다시 물을 필요가 없어야 한다. 실제로 쓰인 라벨만 싣는다.

## `[사고]` 작성 — 이 스킬의 핵심

`[사고]`는 "그 시점의 사용자 머릿속"을 복원하는 칸이다. 여기가 무너지면 문서 전체가 정답표로 되돌아간다.

### 무엇을 쓰는가

**눈앞에 있던 재료 + 적용한 규칙 + 그 결과.** 이 셋의 연결로 쓴다.

```
[사고]
규정 ①의 형태를 그대로 옮겼다. `S.역할 == "finance_reader"`가 눈앞에 있었고,
그것은 `속성 == 상수` 모양이었다. 그래서 조건 X도 오른쪽에 상수를 놓았다.
아직 "등호 오른쪽에 상대편의 속성이 올 수 있다"는 발상이 없는 상태.
```

관찰 가능한 것만 쓴다 — 직전 턴에 무엇이 제시됐는지, 그 답이 어떤 패턴과 같은 모양인지, 무엇이 빠졌는지. 이것들은 대화 기록에서 확인된다.

### 무엇을 쓰지 않는가

**심리 추측.** "긴장해서", "귀찮아서", "자신 없어 보인다" — 대화에 근거가 없다. 사용자가 몇 달 뒤 읽을 때 이런 서술은 정보가 아니라 소음이다.

**질책.** `[사고]`는 오답 해설이 아니다. "왜 틀렸는가"가 아니라 **"왜 그때는 그것이 맞아 보였는가"**를 쓴다. 틀린 답에도 대개 정당한 경로가 있고, 그 경로를 복원하는 것이 재발 방지에 쓸모 있다.

### 정답에도 붙인다

맞힌 답을 그냥 넘기면, 나중에 읽을 때 **왜 그게 됐는지**를 알 수 없다. 잘 되는 사고 경로도 기록 대상이다.

```
[사고]
반례 두 개가 대칭으로 배치되자(과잉 판정 / 과소 판정) 개별 오류가 아니라
방식 자체의 결함으로 일반화됐다. 그리고 누락된 정보를 스스로 명명했다 —
"이 사람의 신분". 진행자가 준 적 없는 표현.
```

### 재발 방지 메모

패턴화 가능한 지점에만 한 줄 덧붙인다. **매번 붙이지 않는다** — 전부에 붙으면 훈계가 되고, 진짜 중요한 것이 묻힌다.

```
스스로 점검할 지점: *뒤집었을 때 무엇이 자리를 바꾸는지 값이 아니라 대상 단위로 확인할 것.*
```

### 진행자 오류

진행자(Claude)가 잘못 짚었거나 질문이 결함이었던 구간은 **그렇게 표시한다.** 사용자의 사고 오류로 기록되면 다음에 읽을 때 잘못된 자기 진단이 된다.

```
> `[진행자 오류]` 여기서 진행자가 X를 잘못 짚어 재확인을 요구했고,
> 같은 답이 반복됐다. 진행 쪽 실수이며 학습 내용과 무관하다.
```

`[막힘]`도 마찬가지다. 원인이 사용자의 이해 부족인지 질문 결함인지 구별해 적는다. 대개 둘 다이며, 둘 다 적는 편이 정확하다.

## 문서 구조

```markdown
# [주제] — 학습 기록

> 한 줄 설명 + 원문 보존 방침 명시

## 라벨 범례
[실제 쓰인 라벨만 표로]

---

# 앵커 N — [앵커 문장]

**시작 지반:** [0단계에서 확인된 사전 지식 수준]
**고른 방향:** [여러 갈래 중 사용자가 고른 것]

## N-0. 재료
[사실] 블록들

## N-1. [그 구간이 다룬 것 — 내용으로 이름 짓는다]
[상황] / [질문] / [응답] / [사고]

## N-2. ...

## [도달] 앵커 N 결론
[사용자가 세운 결론만. 진행자 설명 금지]

---

# 이 세션에서 반복된 사고 패턴
[여러 구간에 걸쳐 반복된 것들. 아래 규칙 참조]

# [미해결]
# 다음에 이어갈 방향
# 출처
```

### 절 제목 붙이기

`1-1`, `1-2` 같은 번호만으로는 나중에 찾지 못한다. **그 구간이 무엇을 다뤘는지 내용으로 이름 붙인다.**

- 나쁨: `1-2. 두 번째 질문`
- 좋음: `1-2. 질의 비용 — 대칭성의 함정`

제목에 그 구간의 **성격**까지 담으면 목차만 훑어도 흐름이 보인다.

### 「반복된 사고 패턴」 절

이 절이 문서를 단순 로그와 갈라놓는다. 개별 `[사고]`는 흩어져 있지만, 문서 전체를 관통하는 경향은 따로 뽑아야 보인다.

- **여러 구간에서 반복된 것만** 올린다. 한 번 나온 것은 해당 `[사고]`에만 둔다
- **어느 절에서 나왔는지 표시한다** — `(1-2, 1-8, 2-7)`. 되짚을 손잡이가 된다
- **잘 되는 패턴도 반드시 포함한다.** 실패 목록만 나열하면 자기 비하 문서가 된다
- 대개 5~8개. 억지로 채우지 않는다

```markdown
**2. 값을 대입하면 거의 항상 풀린다 (1-2, 1-8, 2-7)**
`O.담당의사 == doctor` → `"dr_kim" == doctor`로 대입한 순간 교정.
반대로, 대입 없이 되묻기로 넘어간 구간(2-5)에서는 추측이 나왔다.
```

### 출처

대화에서 언급된 표준·논문·문서를 목록으로 남긴다. 흘려 말한 것도 포함한다 — 나중에 확인할 경로가 된다.

## 무엇을 빼는가

기록은 대화의 복사본이 아니다. 다음은 뺀다.

- 진행자의 인사, 확인 요청, 다음 단계 안내
- 같은 재료의 단순 재게시 (`[지금까지]` 블록은 예외 — 그 시점의 정리 상태를 보여준다)
- 사용자가 라벨 뜻이나 진행 방식을 물은 메타 대화
- 최종 결론에 흡수된 중간 서술

다음은 **절대 빼지 않는다.**

- 사용자의 답변 (틀린 것 포함)
- 오답에서 정답으로 가는 `[정정]` 구간 전체
- `[막힘]`과 그것을 푼 방법
- `[갈래]` — 선택하지 않은 쪽도 남긴다. 나중에 다른 선택을 검토할 때 필요하다
- 앵커에 도달하지 못하고 끝난 것 (`[미해결]`)

## 원문 보존

`[응답]`은 **오타, 비문, 띄어쓰기 오류를 포함해 그대로** 옮긴다.

- 고치지 않는다. 급하게 쓴 답과 신중하게 쓴 답의 차이가 정보다
- 문장이 중간에 끊겼으면 끊긴 채로 둔다
- 여러 줄이면 줄바꿈까지 보존한다

원문이 이해를 방해할 정도로 압축돼 있으면, 고치지 말고 `[사고]`에서 풀어 쓴다.

## 파일 출력

- 마크다운(`.md`)으로 저장하고 `present_files`로 제시한다
- 파일명은 주제를 담는다 — `session_log.md` 말고 `권한모델_학습기록.md`
- 사용자 언어를 따른다

## 안 할 것

- **요약.** 결론만 남기면 이 문서의 존재 이유가 사라진다
- **원문 교정.** 오타를 고치는 순간 그 시점의 상태가 지워진다
- **심리 추측.** `[사고]`는 관찰된 것만 쓴다
- **정답 판정만 적기.** "정답", "오답"만 있고 경로가 없으면 정답표다
- **틀린 답 삭제.** 오답이 정정되는 구간이 이 문서에서 가장 정보량이 많다
- **진행자 실수를 사용자 오류로 기록하기**
- **모든 `[사고]`에 훈계 붙이기**
- **실패 패턴만 나열하기.** 잘 되는 사고도 기록 대상이다
- **타인용 문체.** 독자는 사용자 본인이다. 배경 설명이나 변명조의 서술은 필요 없다
