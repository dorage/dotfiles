# 문서화 규칙 (scribe 플러그인)

코드를 바꾸면 문서도 같은 커밋(또는 같은 PR)에서 함께 바꾼다. 바뀐 게 없는 항목의 문서는 건드리지 않는다.

- 다음이 바뀌면 `README.md` 를 갱신한다.
  - 프로젝트 디렉터리 구조
  - 설치 방법, 가동 전 수동 절차
  - `package.json` 의 scripts
  - 요구사항 (런타임, 도구, 버전)
  - 사전설정 (환경변수, 설정 파일, 계정)
- 다음이 바뀌면 `docs/` 아래 해당 문서를 갱신한다. 문서가 없고 그 항목이 실제로 바뀌었으면 새로 만든다.
  - 코드 컨벤션 -> `docs/convention.md`
  - 테스팅 원칙 -> `docs/testing.md`
  - API 엔드포인트 -> `docs/api-endpoint.md`
  - API 버저닝 -> `docs/api-versioning.md`
  - 동작 방식 -> `docs/how_it_works.md`
- 코드 변경이 있는 턴을 끝내려 하면 Stop 훅이 위 항목의 체크리스트를 한 번 넣어 응답을 되돌린다. 각 항목에 "해당 없음" 또는 "갱신함 (파일명)" 으로 답하고, 필요한 문서를 고친 뒤 응답을 마무리한다.
