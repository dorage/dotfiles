# side-issue 점검 (Stop 훅이 응답을 한 번 붙잡았다)

이번 턴의 작업을 되돌아보고, 아래 두 갈래에 해당하는 것을 골라 `side-issue` 스킬(A. 포크 띄우기)로 이슈화한다.
이슈 작성은 백그라운드 포크가 맡으므로 메인 작업은 막히지 않는다. 이 점검 응답은 짧게 끝낸다.

## 골라낼 것

- 추후 해야 할 일: 이번 턴에서 "나중에", "별도로", "후속으로" 하기로 하고 지금 하지 않은 것. 남겨둔 TODO, 건너뛴 테스트, 임시 우회, 마스터에게 "다음에 하겠다"고 말한 것. 요약 앞에 `후속:` 을 붙인다.
- 지금 작업과 무관한 문제: 조사·구현 중 눈에 띄었지만 이번 완수조건 밖이라 손대지 않은 버그, 컨벤션 결손, 잠복 이슈, 문서와 코드의 불일치.

## 제외할 것

- 이번 세션에서 이미 이슈화한 것, 이번 턴 안에서 해결한 것, 마스터가 하지 않기로 결정한 것.
- 근거(파일:라인, 실측, 재현 경로)를 댈 수 없는 막연한 걱정.
- cwd 가 GitHub 원격이 있는 git 리포가 아니면 이슈화하지 않고 항목만 한 줄씩 적는다.

## 절차

- 해당 항목이 없으면 한 줄만 답한다: `[side-issue] none`
- 있으면 항목마다 `/side-issue {한 줄 요약. 핵심 근거 파일:라인 힌트 포함}` 을 실행해 포크를 띄우고 즉시 돌아온다. 마지막 줄에 `[side-issue] forked=N` 을 적는다.
- 이 점검 응답에서 코드 수정, 커밋, 새 작업 착수를 하지 않는다. 질문도 하지 않는다.
