# side-issue: 발견한 무관 문제를 백그라운드 포크로 이슈화

## 왜 포크인가

발견 맥락(근거 파일:라인, 실측, 재현 경로)은 메인 세션의 컨텍스트에 있다.
서브에이전트로 위임하면 그 맥락을 프롬프트로 전부 직렬화해야 하고, 메인에서
직접 쓰면 gh 왕복과 이슈 작성이 메인 작업의 컨텍스트를 오염시킨다.
`--fork-session` 은 컨텍스트를 통째로 물려받아 직렬화가 필요 없고,
`--bg` 는 즉시 반환해 메인을 방해하지 않는다.

## 분기: 지금 어느 쪽인가

인자에 `--fork` 마커가 **없으면** 메인 세션이다 → [A. 포크 띄우기].
인자가 `--fork` 로 시작하면 포크된 세션이다 → [B. 이슈 작성].

## A. 포크 띄우기 (메인 세션)

1. 자기 session_id 를 컨텍스트에서 찾는다. 이 플러그인의 SessionStart 훅이
   `current session_id: {uuid}` 형태로 주입해 준 값이다.
   - **컨텍스트에 없으면 포크하지 않는다.** 최신 transcript 파일 등으로
     추측하는 것은 금지 — 병렬 세션이 많으면 남의 세션을 포크하게 된다
     (2026-08-26 실증: 최신 jsonl 휴리스틱으로 다른 세션을 포크했다).
     이 경우 마스터에게 "이 세션은 플러그인 훅이 없는 상태로 시작돼
     session_id 를 몰라요. `/prerequisite` 로 환경을 점검하고 새 세션에서
     다시 시도해 주세요"라고 알리고, 이슈 본문 초안만 출력한다.
2. 다음 명령을 실행하고 즉시 본 작업으로 복귀한다:

   ```bash
   claude --resume {session_id} --fork-session --bg \
     --name "이슈화: {문제를 요약한 짧은 한글 제목}" \
     "/side-issue --fork {문제 한 줄 요약. 필요하면 핵심 근거 파일:라인 힌트를 덧붙인다}"
   ```

   - `--bg` 와 `--print` 는 충돌한다. 프롬프트는 positional 로 준다.
   - 출력의 잡 id(`claude logs {id}` 안내)를 마스터에게 한 줄로 알린다:
     "발견한 {문제}를 백그라운드 포크(잡 {id})로 이슈화하고 있어요."
3. 결과를 기다리지 않는다. 마스터가 원하면 `claude logs {id}` 로 확인한다.

## B. 이슈 작성 (포크된 세션)

너는 방금까지 어떤 작업을 하던 세션의 포크다. 컨텍스트에 발견 맥락이 그대로 있다.
`--fork` 뒤의 인자가 이슈화할 문제다.

### 제약

- **이슈 생성 외 부작용 금지**: 코드 수정·커밋·푸시·설정 변경을 하지 않는다.
  파일 읽기와 `gh` 조회·이슈 생성만 한다.
- 근거가 컨텍스트에 부족하면 리포지토리를 읽어 보강한다 (읽기 전용).

### 자족성 기준

이슈 본문만 읽고 누구든(사람·에이전트) 바로 해결에 착수할 수 있어야 한다.
"대화에서 봤듯이" 같은 컨텍스트 의존 표현 금지. 다음 구조로 쓴다:

1. **배경** — 어떤 작업 중 어떻게 발견됐는지 (발견 출처 PR/이슈/세션 링크)
2. **근본 원인 / 현상** — 근거 파일:라인, 실측치, 재현 경로
3. **수선 방향** — 선택지가 갈리면 2~3개를 트레이드오프와 함께
4. **완수 조건** — "이게 되면 끝"을 기계적으로 확인 가능한 형태로
5. **참고 링크** — 관련 이슈·PR 상호 링크

### 절차

1. cwd 의 `git remote get-url origin` 으로 대상 리포를 판별한다.
2. 컨텍스트에서 근거를 회수하고, 부족한 부분은 파일을 읽어 채운다.
3. 제목은 conventional 유사 prefix (`fix:`/`test:`/`docs:`/`ci:` 등) + 한글 서술.
4. `gh label list` 로 존재하는 라벨만 붙인다 (없으면 생략).
5. `gh issue create` 로 업로드. 관련 이슈가 있으면 그쪽에 상호 링크 코멘트를 남긴다.
6. 마지막 응답에 이슈 URL 을 명시하고 종료한다. 후속 작업을 시작하지 않는다.
