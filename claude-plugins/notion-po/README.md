# notion-po

Notion CLI(`ntn`) 기반 **개발팀 PO(Product Owner) 보조** 플러그인이에요. Notion 의 개발 스크럼 보드(스프린트·백로그·에픽)를 터미널에서 운영해요.

두 조각으로 구성돼요:

- **`notion` 스킬** — 범용 Notion CLI(`ntn`) 조작 (페이지 읽기/쓰기, data source 쿼리, 임의 API). 인증·안전 규칙의 단일 출처.
- **`po` 스킬 + `/po` 커맨드** — 위 스킬을 이용해 스프린트/백로그를 다루는 PO 업무 자동화.

## 사전 준비

1. `ntn` CLI 설치 및 로그인:
   ```bash
   ntn whoami          # 인증 확인
   # 미인증이면: ntn login  (브라우저 필요)
   ```
2. 대상 Notion 워크스페이스에 스크럼 보드가 존재하고, 로그인한 계정(또는 봇)이 접근 권한을 가질 것.

## 커맨드

### `/po sprint init {1~4}`

가장 가까운 **다가오는 월요일**부터 **N주간**(월~일 전체) 진행할 스프린트를 스프린트 DB 에 생성해요.

- 시작일 = 오늘 이후 가장 가까운 월요일 (오늘이 월요일이면 오늘)
- 종료일 = 시작일 + (N×7 − 1)일
- 이름 = `[{시작일 YYMMDD}-{종료일 YYMMDD}]스프린트` placeholder (이후 `update` 로 요약 교체)
- 빈 스프린트(제목 + 기간)만 생성. 백로그 연결·상태는 건드리지 않아요.

```
/po sprint init 2
→ 시작 2026-07-27(월) ~ 종료 2026-08-09(일), "[260727-260809]스프린트" 생성
```

같은 시작일의 스프린트가 이미 있으면 만들지 않고 먼저 확인해요.

### `/po sprint plan {1~4}`

`init` 이 빈 스프린트만 만든다면, `plan` 은 **스프린트를 만들고 백로그까지 채워요**. 근거는 이번 주 스프린트 페이지의 **회고 회의노트**와 **백로그 DB 의 실제 상태** 둘뿐이에요.

1. 다음 스프린트 생성 (중복 시작일 확인 후)
2. 이번 주 회고의 액션 아이템·"다음주 계획" 과 백로그 상태를 수집
3. **이월 판정** — `스테이징`은 원 스프린트에서 마무리(이월 안 함), `진행 중`은 잔여만 분리해 재스코어링, 미착수는 값 복제
4. **중복 검사** — 회고 항목이 백로그에 이미 있는지 전체 대조(페이지네이션 필수). 있으면 제품→스프린트로 이동, 없으면 신규 생성
5. **한 건씩 확인** — 신규 항목은 항목 문장·선제조건·완수조건을 보여주고 하나씩 승인받아요
6. **스코어링** — `backlog-scoring` rubric 으로 4종 점수와 가치판단 작성 (스파이크는 공란)
7. **용량 점검** — WIP 합계와 작업자별 부하를 직전 스프린트와 비교해 과부하를 경고
8. **제목 갱신** — 백로그를 관통하는 한 줄 요약으로 placeholder 교체

```
/po sprint plan 1
→ [260810-260816] 생성 → 회고 조회 → 이월 3건·제품이동 4건·신규 7건 → WIP 43pt (직전 23pt, 과부하 경고)
```

보드 정합성도 함께 봐요 — 상태가 `스프린트`인데 어느 스프린트에도 연결되지 않은 **고아 항목**을 찾아 처리를 물어봐요. 자세한 규칙은 `skills/sprint-plan/SKILL.md`.

### `/po sprint update`

어떤 스프린트를 정리할지 **먼저 물어본 뒤**, 그 스프린트에 연결된 백로그들을 근거로 스프린트를 한 줄로 설명하는 제목을 지어 `이름` 을 교체해요.

1. 스프린트 목록(제목 + 기간)을 보여주고 대상 선택
2. 선택한 스프린트의 백로그를 조회 (`취소` 제외), 필요 시 에픽 테마 확인
3. 백로그를 관통하는 30자 내외 한국어 테마 요약을 짓고 `[{시작일 YYMMDD}-{종료일 YYMMDD}]{요약}` 형식으로 제목 생성
4. (대화형이면) 새 제목 확인 후 교체 — 기존 제목은 로그로 남겨 되돌림 대비

```
/po sprint update
→ 스프린트 선택 → "[260727-260803]카페 선결제·EasyPay 도입과 매출·정산 현황 개선" 으로 이름 교체
```

### `/po sprint report`

이번 주 스프린트 페이지 **최상단**에 보고용 브리핑을 작성해요 — 지난 스프린트에서 **누가 어떤 작업을 했는지**(회고/리뷰 회의노트 요약·이월/취소 기록·백로그 상태 근거)와 이번 스프린트에서 **누가 어떤 작업을 할지**를 작업자별로 정리해요.

1. 오늘 날짜로 이번/지난 스프린트를 판정 (애매하면 확인)
2. 지난 스프린트 페이지의 회고/리뷰 요약·이월/취소 기록과 양쪽 스프린트의 백로그(상태·작업자·포인트)를 수집
3. 작업자별 "한 일 / 할 일" 브리핑을 지어 (대화형이면) 확인받고, blocks API 로 페이지 최상단에 삽입
4. 재실행하면 기존 브리핑을 새 것으로 교체 (새 것 삽입 성공 확인 후 옛 것 삭제)

`ntn pages edit`(전체 덮어쓰기)는 회의노트 파손 위험 때문에 쓰지 않아요. 자세한 규칙은 `skills/sprint-report/SKILL.md`.

## 백로그 이월 규칙

- 이전 주의 스프린트에 포함되어 있던 백로그는 다른 스프린트로 옮기지 않아요. `⚡ 스프린트` relation 은 1개 제한이라 옮기면 원 스프린트의 WIP 기록이 사라져요.
- 완료되지 못한 작업은: 해당 백로그의 `지연사유` 속성에 사유와 이월처를 적고, 잔여 작업으로 신규 백로그를 만들어 새 스프린트에 연결해요.

| 상태 | 처리 |
| :-- | :-- |
| `스테이징` | 이월하지 않아요 — 검증만 남은 단계라 원 스프린트에서 마무리 (팀 전례) |
| `진행 중` | 잔여만 분리해 신규 생성 + 재스코어링 |
| `스프린트`(미착수) | 값(점수 4종·가치판단·에픽·작업자) 그대로 복제 |

## 설치

이 플러그인은 dotfiles 리포의 로컬 마켓플레이스 `dotfiles`(`~/workspace/dotfiles/claude-plugins`)에 속해요.

```sh
claude plugin marketplace add ~/workspace/dotfiles/claude-plugins   # 이미 등록돼 있으면 생략
claude plugin install notion-po@dotfiles
```

설치 후 `/po` 커맨드와 `notion`·`po` 스킬이 활성화돼요.

## 안전 원칙

- 읽기(조회·쿼리)는 바로, 쓰기(페이지 생성·제목 교체)는 대상·부모를 규칙과 대조하고 애매하면 확인 후 실행.
- 페이지 생성은 `ntn pages trash` 로, 제목 교체는 로그에 남긴 이전 값으로 되돌릴 수 있어요.
- 인증 토큰 값은 출력에 노출하지 않아요.

## 디렉터리 구조

```
notion-po/
├── .claude-plugin/plugin.json
├── README.md
├── commands/po.md              # /po 디스패처
├── references/
│   └── scrum-playbook.md       # 스크럼 실전 플레이북 (WSJF·벨로시티·스파이크 등 운영 원칙)
└── skills/
    ├── notion/                 # 범용 ntn CLI 스킬
    │   ├── SKILL.md
    │   └── reference.md
    ├── po/SKILL.md             # PO 도메인 지식 + 워크플로우 (리소스 ID·속성·규칙)
    ├── backlog-scoring/SKILL.md # 백로그 평가(작업크기·가치·긴급도·위험도·가치판단) rubric
    ├── sprint-plan/SKILL.md    # 스프린트 생성 + 백로그 구성 (이월·제품이동·신규생성·스코어링·용량점검)
    └── sprint-report/SKILL.md  # 스프린트 브리핑 (지난 스프린트 한 일 / 이번 스프린트 할 일)
```

## 참조 문서

`references/scrum-playbook.md` — 스크럼을 "우리 팀에서 어떻게 굴릴지" 정리한 실전 플레이북. 백로그 계층(에픽·스토리·스파이크), 상대 추정(스토리 포인트), WSJF 우선순위, 벨로시티 용량계획, 긴급 건·상급자 개입 대응을 담아요. `po`·`backlog-scoring` 스킬이 판단 근거로 참조해요.
