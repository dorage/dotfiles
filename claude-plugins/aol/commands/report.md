마스터가 실제로 친 프롬프트에서 반복되는 요청을 찾는 커맨드예요. 입력 인자: `$ARGUMENTS`

찾는 것은 **요청의 형태**예요. 대상이 아니에요. "정산 필드 추가하는 계획 세워줘" 와 "status 컬럼 제거할 계획 작성" 은 대상이 완전히 다르지만 같은 요청이에요. 이런 게 여러 세션에서 반복되면 스킬로 만들 값어치가 있어요.

## 절대 하지 않는 것

**분류표를 먼저 만들고 프롬프트를 거기에 배정하지 않아요.**

이게 이 커맨드의 존재 이유예요. 고정된 목록이 있으면 새로운 형태의 요청이 들어와도 "이거 기존 항목이랑 비슷하네" 하고 밀어넣게 돼요. 그 순간 새 추상화가 사라져요. 목록에 맞추는 압력은 언제나 새것을 지우는 쪽으로 작동해요.

그래서 매번 원문을 처음부터 다시 읽고 아래에서 위로 묶어요. 묶음 이름은 다 읽고 난 뒤에 붙여요. 지난달 리포트의 묶음 이름을 가져다 쓰지 않아요. 같은 이름이 자연스럽게 다시 나오면 그건 진짜 반복이고, 안 나오면 그때 그 묶음은 없던 거예요.

묶이지 않는 프롬프트는 억지로 묶지 않아요. "안 묶임" 으로 그대로 남겨요. 이번 달에 1건이던 게 다음 달에 3건이 되면 그때 새 묶음이 돼요. 미리 만든 칸에 넣어버리면 그 3건은 영원히 안 보여요.

## 원문 뽑기

로그는 `~/.claude/aol/{host}-{YYYY-MM}.jsonl` 이에요. 한 줄에 JSON 레코드 하나예요.

```bash
cd ~/.claude/aol
jq -r 'select(.type=="Q") | [.sid, .repo // "-", .ts, (.prompt|gsub("\n";"⏎"))] | @tsv' *.jsonl
```

`v:1` 시절 레코드가 섞여 있으면 두 가지를 손봐야 해요. `v:2` 부터는 훅이 알아서 걸러요.

- `<` 로 시작하는 시스템 주입 프롬프트가 `Q` 에 들어가 있어요. `grep -v $'\t<'` 로 빼요. `v:2` 는 `SYS` 로 따로 남겨요
- `/Users/...` 같은 드래그 프롬프트가 `SKILL` 로 잘못 들어가 있어요. 되살려서 모수에 넣어요

```bash
jq -r 'select(.type=="SKILL" and .via=="prompt" and (.skill|test("/|Users")))
       | [.sid, .repo // "-", .ts, "/" + .skill + " " + (.args // "")] | @tsv' *.jsonl
```

시스템이 밀어넣는 문장 중에 태그가 안 붙은 것도 있어요. `Your claude.ai usage limit has reset` 로 시작하는 것, `Background agent ... was stopped by the user` 같은 것들이에요. 읽다가 보이면 모수에서 빼고, 몇 건이었는지 리포트에 적어요.

## 읽기

**샘플링하지 않아요.** 뽑힌 프롬프트를 전부 읽어요. 반복은 빈도가 낮은 쪽에도 숨어 있고, 샘플링은 정확히 그걸 놓쳐요. 양이 많으면 나눠 읽되 빠뜨리지 않아요.

읽으면서 각 프롬프트에 대해 한 가지만 물어요. **"대상을 지우면 뭐가 남는가."**

- `cafe_order_seller 테이블에서 status 상태를 제거할 계획작성` → 대상을 지우면 "계획 작성 요청" 이 남아요
- `runs/34074730708/job/101598510132 확인.` → "CI 실패 원인 확인 요청" 이 남아요
- `커밋해.` → "커밋 요청" 이 남아요

남은 것이 같으면 같은 묶음이에요. 문자열이 비슷한지는 보지 않아요. 자연어라 표현이 매번 달라서 문자열 일치로는 아무것도 안 묶여요.

## 세션 수 세기

묶음마다 **서로 다른 `sid` 가 몇 개인지**를 세요. 총 건수보다 이게 중요해요.

한 세션 안에서 같은 요청이 5번 나온 건 그 세션에서 일이 잘 안 풀렸다는 뜻이지, 반복되는 작업이라는 뜻이 아니에요. 서로 다른 날 서로 다른 세션에서 같은 요청이 나와야 스킬 후보예요.

세션 모수도 같이 적어요. 마스터가 말을 건 세션만 세요. 포크·백그라운드 세션은 LLM 이 만든 프롬프트를 받으니 빼요.

```bash
jq -r 'select(.type=="Q") | .sid' *.jsonl | sort -u | wc -l
```

## 기존 스킬과 대조

묶음을 다 만들었으면 **반드시** 지금 있는 스킬·커맨드와 대조해요. 이걸 빼먹으면 이미 있는 걸 또 만들자고 하게 돼요.

실제로 있었던 일이에요. 2026년 9월 조사에서 "계획 작성" 요청이 11건 나왔는데, `/wt:plan` 커맨드가 이미 있었고 16일간 호출은 0건이었어요. 스킬이 없어서 반복한 게 아니라 있는데 안 쓰인 거였어요.

그래서 묶음마다 셋 중 하나로 판정해요.

- **새 스킬 필요** — 덮는 스킬이 없어요. 어떤 스킬인지 한 문단으로 적어요
- **이미 있는데 안 쓰임** — 스킬이 있어요. 그 스킬의 `description` 을 읽고 왜 발동 안 했는지 적어요. 처방은 스킬을 만드는 게 아니라 발동 조건을 고치거나 CLAUDE.md 에 유도 한 줄을 넣는 거예요
- **값어치 없음** — 반복은 하는데 매번 1분이면 끝나거나, 자동화하면 오히려 판단이 필요한 자리를 가려요

호출 실적은 `SKILL` 레코드로 확인해요.

```bash
jq -r 'select(.type=="SKILL") | "\(.via)\t\(.skill)"' *.jsonl | sort | uniq -c | sort -rn
```

스킬 목록은 저장소에서 읽어요. `configs/claude/skills/*/SKILL.md` 와 `claude-plugins/*/commands/*.md`, `claude-plugins/*/skills/*/SKILL.md` 의 frontmatter `description` 이 실제 발동 조건이에요.

## 곁다리 신호

스킬 후보는 아니지만 같이 나오는 것들이에요. 리포트 끝에 절 하나로 붙여요.

- `ASK` 의 `header` 가 서로 다른 세션 3개 이상에서 같으면, 스킬이 아니라 **CLAUDE.md 기본값** 후보예요. LLM 이 매번 묻는 걸 미리 정해두면 되는 거예요
- `CORR` 의 `rule` 이 2회 이상 같으면 **훅** 후보예요. 같은 규칙을 반복해서 어긴다는 뜻이라, 규칙을 더 잘 써놓는 것보다 기계가 막는 게 싸요
- `STOP` 의 `turns`·`tools`·`sec` 중앙값으로 묶음별 비용을 재요. 빈도가 같으면 비싼 쪽이 먼저예요. `sec` 에는 마스터 답을 기다린 시간이 섞이니 `ASK` 가 낀 구간은 빼고 보세요

## 리포트

`claude-plugins/aol/reports/{YYYY-MM-DD}-skill-candidates.md` 로 써요. 형식은 이래요.

```markdown
# {기간} 스킬 후보

모수: 마스터 프롬프트 {N}건 / 세션 {M}개 / {시작일}~{종료일}
제외: 시스템 주입 {X}건

## {묶음 이름}

{N}건 / 세션 {M}개 / 판정: {새 스킬 필요 | 이미 있는데 안 쓰임 | 값어치 없음}

원문 (서로 다른 세션에서):

> {원문 1}
> {원문 2}
> {원문 3}

대상을 지우면 남는 것: {한 문장}

{판정 근거. "이미 있는데 안 쓰임" 이면 그 스킬 이름과 description 을 읽고 왜 발동 안 했는지}

## 안 묶인 프롬프트

{N}건. 억지로 묶지 않았어요.

- {원문 요약} — {왜 안 묶였는지 짧게}

## 스킬 아닌 후보

### CLAUDE.md 기본값
### 훅
```

묶음별 건수의 합과 안 묶인 건수를 더하면 모수와 같아야 해요. 다르면 어디선가 프롬프트를 흘린 거예요.

## 다 쓰고 나서

스스로 한 번만 물어요. **"묶음 이름을 먼저 정해놓고 거기에 프롬프트를 넣었는가?"**

그랬다면 이 커맨드가 막으려던 걸 그대로 한 거예요. 안 묶인 프롬프트가 0건이면 특히 의심해요. 억지로 다 밀어넣었다는 신호예요.
